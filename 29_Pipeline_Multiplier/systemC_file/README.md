# `pipeline` SystemC 转换说明

## 建模范围

SystemC DUT 名为 `pipeline`，与 RTL 顶层同名。模型按 `pipeline.v` 的寄存器级和组合连接实现，不替 RTL 修正算术结构或流水对齐。所有时序状态在 `clk` 上升沿更新；`reset` 是同步高有效，只将 `xtemp`、`ytemp` 置零。其他流水寄存器不复位，初态保留四态未知值。RTL 的 `if (reset)` 遇到 X/Z 时走正常采样分支，模型也按此处理。

每个上升沿的右值均从旧寄存器快照计算，再统一写入新值，以保留 RTL 多个非阻塞时序过程的并行更新语义。递归乘法器实现 `vdcmul_32b` 至 `vdcmul_2b` 的可达算术结构；加法器按 `rca_1b` 的 XOR 与三项 majority carry 表达式逐位运算，避免用可能改变四态 X 传播的代数替换。

从输入第一次被时钟采样起，输入寄存器、部分积、交叉项/进位、最高段依次更新；当输入保持稳定时，经过 5 个上升沿后，`prod` 收敛到无符号 `x*y`。但 RTL 的输出直接拼接 `temps3`、`temps2[31:0]`、`temp1[31:0]`，没有输出 valid 或对低位片段增加对齐寄存器。因此连续每拍变化的输入不应被解释为具有每拍一笔、统一事务延迟的流水接口；转换保留这种源 RTL 行为。

## 最小可达模块闭包

按 `pipeline` 顶层实例和递归模块实例，转换采用以下**唯一模块定义**：

- `pipeline`
- `vdcmul_32b`、`vdcmul_16b`、`vdcmul_8b`、`vdcmul_4b`、`vdcmul_2b`
- `rca64`、`rca32b`、`rca16b`、`rca8b`、`rca_4b`、`rca_1b`
- `half_adder`

其中 `rca_1b` 取自 `rca_4b.v`；不纳入也不编译含重复 `rca_1b` 定义的 `rca_4b1.v`。`half_adder` 在独立 `half_adder.v` 与 `vdcmul_4b.v` 中各有一份同名定义，闭包只保留一个模块定义。`vdcmul_64b.v`、`rca_4b1.v` 不在 `pipeline` 的可达实例层级内。原 RTL 的递归 include 没有 include guard，且多个路径会重复文本包含依赖；因此不把目录内所有 `.v` 盲目并入一个源文件清单。SystemC 包是按上述去重后的可达模块行为建模，没有声称原 RTL 源文件本身已被编译。

## 分层迁移记录

1. 叶级：将 `rca_1b` 的逐位 XOR/三项进位规则、`half_adder` 与 `vdcmul_2b` 映射为四态 helper。
2. 组合层：同一递归模型逐级覆盖 `vdcmul_4b/8b/16b/32b` 和 `rca_4b/8b/16b/32b/64`，保留旧状态采样与 X/Z gate 传播。
3. 顶层：`pipeline` 各 posedge 寄存器过程由旧状态快照推进，建立公开端口契约并在集成层运行稳定输入与逐拍变化回归。

这是单一顶层、单时钟、重复组合层级；没有 CDC、存储宏、厂商原语或 DPI/PLI。各层随顶层包共同构建，自检覆盖叶级算术结果、递归乘法和顶层寄存器时序；没有独立叶级 RTL 工程入口。Makefile 对去重闭包中的 RTL 文件计算 SHA-256 聚合标识并写入 `simulation.log`，同时记录固定随机 seed 以绑定测试配置和源文件。

## 自检范围与限制

自检对固定输入保持 5 个上升沿后，用独立的 128 位乘法 oracle 核对输出；覆盖零值、边界、进位压力向量及固定 seed `0x29D1B54A32C0FFEE` 的 16 个 xorshift64 用例。另有独立的两态寄存器级 reference 使用原始 32×32 部分积和旧状态推进方程核对 16 个逐拍变化输入；它验证 RTL 当前真实的分段输出时序，而不把流式输入结果错误地当成每拍对应一个完整乘积。定向检查还覆盖初始未初始化输出、同步复位的时钟间行为、复位清空输入级后管线排空，以及 X/Z 输入被零屏蔽和 X/Z 复位条件走正常采样分支。

逐拍变化测试使用独立整数周期参考模型核对当前 RTL 状态转移，但有限向量不等于所有输入序列穷举。该测试不是形式验证或 RTL/SystemC 等价证明。仿真日志、逐项 CSV、自检二进制和 VCD 均放在 `out/`。
